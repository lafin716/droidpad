# 실기기 테스트: 에어 마우스 수정 · 터치패드 지연 · 블루투스 QoS

대상: 폴드(DroidPad) → 갤럭시 탭(호스트). 디버그 APK `app/build/outputs/apk/debug/app-debug.apk`.

## 준비
1. 기존 DroidPad를 쓰던 상태라면 그대로 덮어 설치(`adb install -r …`). 디버그 빌드는 패키지가 `com.droidpad.app.debug`라 릴리즈 앱과 **별도 앱**이므로, 릴리즈 앱이 실행 중이면 종료하세요(HID 앱은 동시에 하나만 등록됨).
2. 탭에서 페어링·연결까지 완료.
3. 로그를 볼 수 있으면 같이 수집: `adb logcat -s HidConnection`
   - 프리셋이 적용될 때마다 `registerApp with QoS <프리셋> QosParams(...)`가 찍힙니다.
4. 기준값: 설정 › 실험실 › 블루투스 QoS = **표준**, 포인터 리포트 간격 = **12 ms** (기본값).

### "끌림(lag) 테스트" 공통 방법
터치패드를 **빠르게 2–3초간 크게 원을 그리다가 손가락을 멈춘 채로** 둡니다.
- 손가락을 멈춘 뒤에도 커서가 계속 따라 움직이면 **끌림 있음** — 대략 몇 초간 따라오는지 기록.
- 멈추는 즉시 커서도 멈추면 **끌림 없음**.
- 이어서 천천히 작은 아이콘을 정확히 맞추기(정밀도) → 체감 기록.

## A. 에어 마우스 버그 수정 확인

| ID | 절차 | 기대 결과 |
|---|---|---|
| A1 | 설정 › 에어 마우스 › "누르고 있을 때만 이동" 켬 → 에어 마우스 열기 → 패드를 누른 채 폰 회전 | 누르는 동안 커서 이동, 떼면 멈춤 |
| A2 | A1 상태에서 패드를 짧게 탭 | 좌클릭 1회, 커서 튐 없음 |
| A3 | "누르고 있을 때만 이동" 끔(항상 이동) → 폰 회전 | 손대지 않아도 커서 이동 |
| A4 | A3 상태에서 패드를 누른 채 폰 회전 | 누르는 동안 커서 **멈춤**(일시정지), 떼면 다시 이동 |
| A5 | 오른쪽 스크롤 띠 위아래로 끌기 | 탭 화면 스크롤 |
| A6 | 실험실 › 책상 마우스 랩에서 속도 슬라이더를 최소/최대로 바꾸며 이동 | 슬라이더 값이 즉시 반영됨 |

## B. 터치패드 지연 (리포트 간격, QoS 표준 고정)

각 간격마다 끌림 테스트 + 정밀도 체감.

| ID | 포인터 리포트 간격 | 기대 결과 |
|---|---|---|
| B1 | 12 ms (기본) | 끌림 없음. 이전 버전(1.2.0)보다 지연이 확실히 줄어야 함 |
| B2 | 제한 없음 | 이전 버전과 비슷한 동작 — **끌림이 다시 생기면 원인 확정** |
| B3 | 8 ms | 끌림 없으면 12 ms보다 부드러울 수 있음 |
| B4 | 16 ms | 끌림 없음, 다소 뚝뚝 끊길 수 있음 |

## C. 블루투스 QoS 프리셋 (간격 12 ms 고정)

각 프리셋 선택 → 연결이 끊겼다가 **자동으로 다시 연결되는지** 확인 → 끌림 테스트 → 기능 회귀(D) 간단 확인.

| ID | 프리셋 | 선언 값 (서비스, tokenRate B/s, bucket, peak B/s, latency µs) | 기대 결과 |
|---|---|---|---|
| C1 | 표준 | 최선형, 800, 9, 0, 11250 | 기존과 동일 |
| C2 | 고대역 | 최선형, 8000, 64, 16000, 11250 | 연결 정상. 빠른 이동 시 C1보다 부드럽거나 같음 |
| C3 | 저지연 | 최선형, 8000, 64, 16000, 7500 | 연결 정상. 체감 지연 감소 가능 |
| C4 | 보장형 | 보장형, 8000, 64, 16000, 7500 | **연결 실패 가능**. 실패하면 "표준"으로 되돌려 복구되는지 확인 |
| C5 | 미지정 | QoS 없음(스택 기본값) | 연결 정상 여부만 확인 |
| C6 | 프리셋 변경 직후 앱 종료 → 재실행 | 선택한 프리셋 유지, 마지막 탭에 자동 재연결 |
| C7 | 연결 실패 상태(오류)에서 다른 프리셋 선택 | 다시 등록 시도 후 연결 |

> 탭이 QoS 값을 무시할 수도 있습니다. 프리셋 간 차이가 없다면 그것도 유효한 결과입니다.
> 가장 좋았던 프리셋 + 간격 조합으로 **B2(제한 없음)**도 한 번 해보면 QoS만으로 끌림이 해결되는지 알 수 있습니다.

## D. 회귀 확인 (가장 좋았던 조합에서)

| ID | 절차 | 기대 결과 |
|---|---|---|
| D1 | 탭 / 두 번 탭 / 두 손가락 탭 / 세 손가락 탭 | 좌·더블·우·가운데 클릭 |
| D2 | 길게 누른 뒤 이동해 아이콘 드래그 | 드래그 중 끊김·놓침 없음 |
| D3 | 두 손가락 세로/가로 스크롤 | 정상, 끌림 없음 |
| D4 | IME로 영문·한글 문장 빠르게 입력, 백스페이스 | 글자 누락·순서 뒤바뀜 없음 |
| D5 | 전체 화면 키보드로 입력 | 정상 |
| D6 | 탭 블루투스 끄고 켜기 / 폴드 화면 끄고 켜기 | 자동 재연결 |

## E. 포인터 보간 (빠른 이동 끊김)

간격 12 ms, QoS는 가장 좋았던 값으로 고정. 터치패드와 에어 마우스 각각 **빠르게 좌우로 크게 왕복**하며 커서가 뚝뚝 끊기는지 봅니다.

| ID | 포인터 보간 | 기대 결과 |
|---|---|---|
| E1 | 끔 | 빠를수록 걸음이 고르지 않음(이전 동작) |
| E2 | 8 ms (기본) | E1보다 고르게 움직임. 손을 멈추면 바로 멈춤 |
| E3 | 16 ms | E2와 비슷하거나 조금 더 부드럽지만 약간 늦게 따라올 수 있음 |
| E4 | 8 ms에서 길게 눌러 드래그 → 빠르게 이동 후 바로 손 떼기 | 놓는 위치가 커서 위치와 같음 |

## F. 즉시 터치 전달 · 센서 스레드 분리

이전 버전(1.3.0) APK와 번갈아 설치해 비교하면 차이가 가장 잘 보입니다. 보간 8 ms, 간격 12 ms 고정.

| ID | 절차 | 기대 결과 |
|---|---|---|
| F1 | 터치패드로 끌림 테스트 + 빠르게 작은 원 그리기 | 1.3.0보다 커서가 손가락을 바로 따라옴, 원이 더 둥글게 그려짐 |
| F2 | 커스텀 레이아웃의 터치패드 칸에서 F1 반복 | F1과 동일 |
| F3 | 에어 마우스 열어 둔 채 화면 회전·알림 내리기 등 UI가 바쁠 때 폰 돌리기 | 커서가 멈칫하지 않음 |
| F4 | 에어 마우스 닫은 뒤 키보드 입력·설정 화면 스크롤 | 정상(다른 화면 동작 변화 없음) |

## G. BLE 연결 방식 (실험)

클래식의 스니프 모드 지터를 피할 수 있는지 보는 시험입니다. 보간 8 ms, 간격 12 ms 고정.

| ID | 절차 | 기대 결과 |
|---|---|---|
| G1 | 설정 › 실험실 › 연결 방식 › **BLE (실험)** 선택 | 클래식 연결이 끊기고 기기 화면에 "탭에서 검색해 연결" 안내 표시 |
| G2 | 탭 블루투스 설정에서 기존 DroidPad **등록 해제** → 새 기기 검색 → DroidPad 선택해 페어링 | 페어링 후 연결됨(키보드·마우스 아이콘). 탭이 목록에 표시하지 않으면 **NG로 기록**(폰을 BLE HID로 인식 못 함) |
| G3 | 끌림 테스트 + 빠르게 좌우 왕복(터치패드·에어 마우스) | 클래식(F1)보다 끊김이 적거나 같음 |
| G4 | IME로 영문·한글 입력, Caps Lock 켜고 끄기 | 글자 누락 없음, Caps 상태 표시 반영 |
| G5 | 앱 종료 → 재실행, 탭 블루투스 끄고 켜기 | 탭이 다시 연결함(자동 재연결) |
| G6 | 연결 방식 › **클래식**으로 되돌리기 | 탭에서 DroidPad 다시 등록 해제 후 기존 방식으로 페어링하면 정상 |
